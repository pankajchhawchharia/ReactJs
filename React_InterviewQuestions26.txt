3. Flexbox is for one-dimensional layouts, while Grid is for two-dimensional layouts. Responsiveness is achieved through Media Queries and fluid layouts.
1. Static (Default)
Every element is static by default. It follows the normal page flow and does not respond to top, bottom, left, or right properties.

2. Relative
The element is positioned relative to its normal position. Setting top: 10px will move it 10 pixels down from where it would usually sit, but the space it originally occupied remains reserved in the layout.

CSS
.box-relative {
  position: relative;
  top: 20px;
  left: 20px;
  background-color: lightblue;
}
3. Absolute
The element is removed from the normal document flow and positioned relative to its nearest positioned ancestor (an ancestor with a position other than static). If no such ancestor exists, it uses the document body.

CSS
.container {
  position: relative; /* This acts as the anchor */
}

.box-absolute {
  position: absolute;
  top: 0;
  right: 0; /* Placed at the top-right of the container */
}
4. Fixed
The element is removed from the flow and positioned relative to the browser window (viewport). It stays in the same place even when the page is scrolled. This is commonly used for navigation bars.

CSS
.navbar {
  position: fixed;
  top: 0;
  width: 100%;
}
5. Sticky
A hybrid of relative and fixed. The element is treated as relative until it crosses a specified threshold (e.g., top: 0) during scrolling, at which point it "sticks" like a fixed element.

CSS
.sticky-header {
  position: sticky;
  top: 0;
  background: yellow;
}

2. Prototypes (Prototypal Inheritance)JavaScript is a prototype-based language. Prototypes are the mechanism by which JavaScript objects inherit features from one another.  How it works:Every object in JavaScript has a built-in property called its prototype.When you try to access a property or method that doesn't exist on an object, JavaScript looks for it in the object's prototype, then the prototype's prototype, and so on, until it finds it or reaches the end of the prototype chain.Code Example:JavaScriptfunction Person(name) {
    this.name = name;
}

// Adding a method to the prototype so all instances share it
Person.prototype.greet = function() {
    console.log(`Hello, my name is ${this.name}`);
};

const user = new Person("Pankaj");
user.greet(); // "Hello, my name is Pankaj"

console.log(Object.getPrototypeOf(user) === Person.prototype); // true

In a senior or specialized React role, interviewers expect you to understand how to optimize the build process manually. Below is the technical breakdown of what "customization" usually entails.

What is Webpack Customization?
Webpack is a module bundler. Customization involves modifying the webpack.config.js file to handle specific file types, optimize file sizes, or manage different environments (development vs. production).  

Key Areas of Customization
Entry and Output: Defining exactly where the app starts and where the final bundle should be saved.

Loaders: Telling Webpack how to process non-JavaScript files (e.g., using babel-loader for JSX or css-loader for styles).

Plugins: Adding advanced functionality, like HtmlWebpackPlugin to generate your HTML file or CleanWebpackPlugin to clear old builds.

Optimization: Implementing Code Splitting or Tree Shaking to keep the bundle size small.

Code Example: A Customized Webpack Config
If the interviewer asked you to create a custom configuration to handle React (JSX) and CSS, a basic customized file would look like this:

JavaScript
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  // 1. Custom Entry Point
  entry: './src/index.js',
  
  // 2. Custom Output Location
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.[contenthash].js', // Use hashes for better browser caching
  },

  module: {
    rules: [
      {
        test: /\.(js|jsx)$/,    // 3. Custom Loader for React
        exclude: /node_modules/,
        use: 'babel-loader',
      },
      {
        test: /\.css$/,         // 4. Custom Loader for Styles
        use: ['style-loader', 'css-loader'],
      },
    ],
  },

  plugins: [
    new HtmlWebpackPlugin({
      template: './public/index.html',
    }),
  ],
  
  // 5. Optimization (Code Splitting)
  optimization: {
    splitChunks: {
      chunks: 'all',
    },
  },
};

9. End-to-End (E2E) testing is a methodology used to test a software web application from start to finish to ensure the entire user flow works as intended. Unlike unit tests (which test a single component) or integration tests (which test how parts work together), E2E tests simulate a real user's behavior in a browser.

Popular E2E Tools (The "Tools" the interviewer was looking for):
Cypress: A modern, developer-friendly framework that runs in the same run-loop as the application.

Playwright: A framework from Microsoft that allows for fast, reliable, and capable cross-browser testing.

Selenium: The traditional industry standard for browser automation.

import { useState, useEffect } from 'react';

function UserTable() {
  const [data, setData] = useState([]);
  const [search, setSearch] = useState('');

  useEffect(() => {
    fetch('https://api.example.com/users')
      .then(res => res.json())
      .then(json => setData(json));
  }, []);

  const filtered = data.filter(user => 
    user.name.toLowerCase().includes(search.toLowerCase())
  );

  return (
    <div>
      <input onChange={(e) => setSearch(e.target.value)} placeholder="Filter..." />
      <table>
        {filtered.map(user => <tr key={user.id}><td>{user.name}</td></tr>)}
      </table>
    </div>
  );
}
